## Real model findings and correction

Workers AI was called through the local workerd adapter using the actual authenticated **Free** account, fictional data only. The first full live set achieved four ordinary tasks; two ordinary responses were malformed at the 2,048-token output bound, one adversarial request timed out, and an adversarial foreign-project response was correctly rejected with 403 (the initial harness incorrectly expected only 400). No failed request automatically changed the document.

The OpenAI-style required-null schema inflated small update responses. A Workers-specific compact schema now makes only the genuinely optional maps optional, while preserving required top-level/operation identity, closed objects and the same mandatory semantic validation. A regression checks that the native schema stays unchanged. With the compact schema, theme, heading, spacing, token and phone-layout tasks passed, as did both adversarial semantic refusals. A layer-name harness used nonexistent `workspace-label`; it was corrected to the actual `workspace-eyebrow`, and that sixth ordinary task passed on its own rerun. Ordinary successful outputs required explicit group acceptance and were read back from storage. These results are controlled small fixtures, not a general model-quality benchmark. The compact release subsequently passed eight public API cases and persistence across its automatic deployment; the deeper UI finding below narrowed what those API checks established.

## Initial local acceptance

A deeper Chromium review/reject/accept journey exposed a missed property-retention invariant: the model supplied only `props.text`, so canonical map replacement removed the heading variant/formatting. This was an actual application integration defect, not a passing UI check. Two failed UI reports are retained privately with the exact scope.

The Workers wire contract now explicitly uses partial maps. A pure decoder expands them against the validated project snapshot in dependency order, preserving untouched properties and responsive breakpoints before the unchanged canonical semantic validator runs. Optional `replaceMaps` makes intentional whole-map replacement/clearing explicit and is removed before canonical review/application. Raw proposal safety inspection runs before normalization, including prototype/accessor/complexity guards. The live evaluation harness now checks retained properties as well as target values. `npm run verify:ai:public` is a controlled real-model Chromium check, deliberately excluded from CI and automatic builds to avoid consuming inference allowances. ## Provider schema compatibility and final staging correction

The partial-map release `67e41c6` passed all five CI jobs, including 365 tests on Windows/Linux, native and workerd browser suites and both container architectures. Its public model call nevertheless failed: the added `replaceMaps.uniqueItems` constraint is unsupported by the provider's xgrammar schema compiler. The actual provider returned HTTP 400/code 8007, while the adapter's generic unavailable response initially obscured this distinction. The account showed 4.9k/10k daily neurons used, so this was not quota exhaustion.

The provider schema now omits `uniqueItems`; the server decoder still rejects duplicate reset controls. HTTP 400 is separately reported as `AI_PROVIDER_CONFIGURATION` (502), distinct from quota/unavailability. Regression tests cover the constrained schema, duplicate controls and configuration error. An isolated actual provider call returned HTTP 200 after the correction.

The complete corrected application then passed **5/5 actual Chromium UI groups with real Workers AI** at private workerd staging (`http://127.0.0.1:4193`): proposal disclosure/no auto-edit/reject; explicit accept and saved reload; same-identity third-attempt refusal; cancelled browser request with no proposal/edit; 390px phone without page overflow. The accepted heading retained all five existing text/format properties. This is private staging evidence, not public acceptance. Report ID: `5b5a97db-b1c8-49c0-856e-53a578c611a3`. Lint, both TypeScript targets and **366 tests in 27 files** passed locally. Real inference checks are explicit commands, never automatic CI/build steps. Failed public UI reports remain preserved; they are not counted as passing checks.
